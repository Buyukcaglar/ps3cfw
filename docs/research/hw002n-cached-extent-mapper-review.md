# Local metadata extent mapper

12 October 2026. `tools/Map-Ufs2SnapshotFile.py` reads only a supplied local `decoded-sector-cache.bin` under project observations, verifies an explicit SHA256, and creates a new local analysis report. It imports no raw-device, network or key-access code. No SSD writer is released. It does not acquire a fresh snapshot; that remains a separately guarded read-only hardware operation after native I/O/restart qualification.

The cached layout is reviewed against the frozen `tools/HW002L-OfflineAudit/UfsVolume.cs` and the independent HW002L interpretation: 520-byte records contain an eight-byte little-endian absolute byte offset and 512 decoded bytes; big-endian UFS2 starts at byte 16384. Geometry is restricted to the recorded Crucial values. Duplicate/unbounded cache records, missing metadata, wrong magic/geometry, malformed directory records, duplicate directory names, unexpected path/type, negative/out-of-range pointers and extents overlapping reserved metadata fail closed. Only explicit project test directories and filenames are accepted. Directory payload reads come from the cache; file payload is never read by the mapper.

Pointer walking uses 12 direct pointers and single/double/triple roots at 0xd0/0xd8/0xe0. Entries are 64-bit big-endian fragment addresses. The mapper accounts separately for logical payload bytes, holes and physical payload spans; it does not confuse final block allocation padding with payload length. Fragment tails for direct-only files follow the frozen volume implementation. Adjacent spans merge only when both logical and physical ranges are contiguous. Bytes beyond the original 1536 GiB device-address gate are counted using absolute device byte addresses, not file offsets.

`analysis/hw002n-extent-mapper/host-tests.json` records 34 passing local checks. Four pretest HW002J files agree with independently decoded inode/size records; missing historical large J and absent new N files are rejected rather than fabricated. Synthetic independently laid-out pointer blocks cover direct/single/double/triple boundaries plus the 4 GiB and 8 GiB file-offset block numbers, sparse holes, bounds and missing metadata. This is host/parser evidence, not fresh physical mapping or target execution. The pretest small J data lies around byte 302 million, with zero bytes past the original gate; it says nothing about where N was newly allocated.

The read-only snapshot is partial and whole-filesystem integrity remains unproven. No claim is made about resolving HW002L's unreachable allocations, payload hashes, physical-device I/O, allocator coverage, full capacity or stable support. A future fresh snapshot and comparison to the native corpus identity are required before applying this mapper to N.
