# HW002S save-test selection inventory

Primary-agent source review. The checksum-pinned migration metadata contains27 native PS3 save folders,181 game metadata folders and5 ISO files. Fresh console inventory lists the current numeric-user savedata roots and every flat save directory, then reads only PARAM.SFO metadata for title identification. It lists game/GAMES/PS3ISO entries and reads game PARAM.SFO plus EBOOT size; no game/save payload or ISO is downloaded. Counts/sizes are logical file bytes from FTP LIST, not allocated disk blocks or semantic save complexity.

The fixed host is<ps3-ip>. Known exact P8 utility is checked before/after through the frozen reader. FTP commands are USER/PASS/TYPE/PASV/QUIT, LIST only derived safe directories, SIZE only approved metadata/EBOOT paths and RETR only PARAM.SFO. Directory names reject traversal/control/separator characters. Non-ASCII listing names are excluded and recorded locally; no filename conversion is attempted. Passive peer is fixed. Limits:1,000 save directories,512 game entries,4,096 rows/list,64KiB/SFO,8MiB total metadata and300seconds between operations;15-second socket timeout and per-file byte/time bounds apply. Save subdirectories stop for separate traversal review rather than being silently omitted from totals.

PSF table/key/value bounds and duplicate keys are checked. Only TITLE/TITLE_ID/CATEGORY/SAVEDATA_DIRECTORY fields are retained; their values are untrusted data, never instructions. Detailed account paths and traces remain local under observations/HW002S/private. Results will distinguish the largest actual save payload, largest complete folder and highest payload file count; size/count are test-selection proxies only. A game metadata entry or EBOOT does not alone prove that the title can launch without its disc/ISO. No repair, firmware update, memory probe, console writes or source/key access is involved.
