The target is dev_flash/sys/internal/libfs_utility_init.sprx, contained in dev_flash_022.tar.aa.2026_01_08_191610. The executable segment grows by0x3000. Original data/BSS is preserved; 128 diagnostic bytes plus a32896-byte component record are appended in owned BSS. All2086 original relocation records are unchanged. Static values referencing moved data are adjusted; four independent segment-base models reproduce all original loaded text/data bytes except the two declared instructions. Six new HA/LO address relocations refer exclusively to new header/path storage. Existing zero runs are not treated as code caves.

At callback export VA10ea0, replacing `extsw r30,r30`, the entry helper atomically claims the first invocation by original stack frame, records actual backing address, requested budget, callback descriptor and opaque context, then reproduces the instruction. At common return VA10ec8, replacing `li r0,0`, the helper requires the matching frame and unconsumed entry, marks it consumed, records original utility status, executes the self-test and logs to USB. It returns r0=0, preserving the original frame, LR, TOC and nonvolatile registers. The original cleanup and status return continue unchanged. Reuse of the same stack frame cannot rerun the helper. No other original instructions or native heap operations are replaced.

The component uses a fixed4096-slot pointer/charge ledger. Native pointers are never dereferenced by it. Geometry and heap identity are checked before authorizing any future prefix read; missing headers, duplicate/unknown pointers, saturation and overflow mark accounting incomplete. Realloc overlap is counted as simultaneous lifetime. A nonblocking try-lock marks a sticky contention bit on failure; a future wrapper must fall back to the original operation and forbid complete-peak claims. No owner spin-wait is introduced. The only atomic reservation retry is the compare/exchange implementation itself, not a wait for the lock owner.

The PowerPC component is compiled by pinned portable Zig0.15.2/Clang for PPC64 freestanding970. Functions are leaf code using only volatile GPRs, no TOC/TLS/stack, nonvolatile CR fields, vector/FPU instructions, external helpers or text relocations. Record fields are volatile32-bit words: the audit found a compiler-generated unaligned64-bit store in an earlier prototype; that prototype was replaced before packaging. The final component has no64-bit memory instructions. Host execution and static ABI checks do not establish Sony execution.
