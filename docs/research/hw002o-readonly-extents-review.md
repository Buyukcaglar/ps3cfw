# HW002O read-only capture review

The current question is allocation of two native-created, fully hashed HW002N files after a normal restart. The completed `observations/HW002N/after-boot/result.json` contains exact expected native MD5 hashes and sizes, a separate exact 4096-byte tail read at 4 GiB, and unchanged full firmware/plugin controls. The contextual user report supports ordinary shutdown/power-on/XMB without repair or format prompts. It does not add a new timing or capacity measurement.

`tools/Capture-HW002O-NativeExtents.py` was reviewed against the frozen mapper and existing CECHA00 crypto/read-only adapter. It opens no raw handle or key until the fixed review bindings, explicit manual-move report, current disk-number agreement and completed native baseline pass. A mismatched fixed folder/file pair stops before crypto load. New local output custody prevents overwriting earlier evidence. The original key is read only after the opened device's serial/USB/length verification; the root bytearray is overwritten after derivation. This is not a claim that Python or its crypto library securely erases every internal key copy. Neither original nor derived key bytes are emitted, hashed, stored in reports or transmitted.

The existing PhysicalReader uses CreateFileW GENERIC_READ and only information-query IOCTLs, SetFilePointerEx and ReadFile. Windows identity requires the exact Crucial serial and size, logical 512, USB, and neither boot nor system; the open handle repeats length, serial and USB checks. No raw write API exists on the adapter. The new helper never calls the older inspector's broad inspect/main routines. It imports only derive_key, decrypt_sectors, partitions and PhysicalReader. The primary partition must start at sector 32 and contain 3,902,834,832 sectors.

MetadataCache permits only primary-partition addresses, requests no larger than 1 MiB, and at most 32 MiB of cumulative rounded metadata reads, including reread overlaps. Cache hits cause no raw I/O. It rejects short input, decoded length mismatch, changed overlapping sectors and short local record writes. Each unique decoded sector is saved as an eight-byte little-endian absolute offset followed by 512 bytes. The disklabel and fixed metadata-anchor checks add small reads outside that cache counter. No target file payload is deliberately read. The mapper follows directory, inode and indirect-pointer metadata only, with reviewed geometry, extent bounds and reserved-region checks. An inconsistent filesystem could mislabel a pointer; this bounded traversal is not an allocation-bitmap integrity audit.

Only the two fixed native test paths are mapped. Exact lengths and no holes are required. Label, superblock, root inode and both target inodes are reread and compared. Clean flag 1 and zero pending blocks are required but explicitly not integrity proof. The local snapshot is flushed/fsynced and independently parsed by Snapshot/Volume to reproduce both mappings before completion. Flush/close nesting closes the raw handle even if local snapshot finalization fails. Such a failure may leave partial evidence without a completed receipt; do not reuse that output directory.

`analysis/dev006/test_hw002o_capture.py` ran 41 host checks. These cover rounding, cache hits/overlaps, record format and replay, partition/end/read-budget bounds, short reads/decryption/write failures, changed metadata detection, actual traversal of four known historical files through a fake read-only source, missing new files, and readiness/review/output/contract gates before a forbidden crypto stub. No real disk, key or network was accessed. The existing mapper's 34 host checks separately cover direct/single/double/triple indirect paths and 4/8 GiB logical boundaries. These tests establish host behavior only, not a fresh capture or native high-device-address exercise.

No candidate firmware, console state, USB contents or concurrent PS3HDDTool-local work changes in this stage. The physical move and current Windows identity are still required. The binding manifest is produced after this review and the host report are saved, with no circular hashes. On success, report exact metadata-derived physical ranges and bytes above the old gate.
