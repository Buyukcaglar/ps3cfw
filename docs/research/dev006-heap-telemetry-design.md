# Checker telemetry findings and next implementation gate

Primary-agent exact-binary investigation, 11 October2026. analysis/dev006/heap-telemetry/static-evidence.json pins captures from the original supplied retail liblv2 and libfs_utility_init; no live heap operation was executed.

The retail exports resolve to _sys_heap_get_mallinfo NIDD1AD4570 VA7204, _sys_heap_get_total_free_size B6369393 VA7300 and _sys_heap_stats8985B5B6 VA7134. Mallinfo takes a heap/output pointer, locks the heap, calls7c44 and copies ten32-bit words. Free-size calls that wrapper and returns its offset0x20. The walker sums current free chunks, including a tail/administrative amount; it is not a remembered minimum-free counter. The field returned at mallinfo offset0x14 comes from heap+0x1b0. Captured initialization8230/8234 writes the same value to heap+0x1b0/+0x1ac. No documented peak-in-use meaning is established. Linear direct-store matches do not rule out indirect/aliased accesses. Neither a post-check free-space read nor a field named max/arena by analogy can establish peak consumption.

The original free routine83a0..83bc uses chunk=pointer-8 and size=word(pointer-4)&0xfffffffc. That is an exact allocator-layout lead, not permission to dereference arbitrary/live stale process addresses. The utility's e6e0 wrapper calls heap malloc; e718 calloc calls it then memset; e770 calls heap free; e7a4 allocates/copies then frees the old buffer. This identifies candidate instrumentation coverage, including realloc's overlapping lifetime, without modifying code.

Historical captured geometry gives a60981796-byte block bitmap plus106496-byte summary,6602*8-byte group table and two small directory tables. setup-request-floor.json calculates the sum of those five requests. It is a lower bound, not a peak, current populated geometry or a128MiB sufficiency proof. The setup capture has no free between those requests, but other baseline allocations/overhead and later passes remain unbounded.

Future telemetry must record invocation/heap identity, epoch, backing range/budget, live charged chunk bytes, maximum, failed requests, allocation/free counts, incomplete/error flags and utility return status. Null/error returns must never trigger a chunk-header read. Every pointer/header/size must be validated against the exact backing interval before telemetry dereferences it; invalid telemetry must mark the observation incomplete without suppressing original checker errors. It must include every allocation lane and realloc overlap, preserve the original return values/ABI, avoid heap allocation/printf/recursive locking in its own fast path, and survive utility teardown through an explicitly owned output record. Synchronization must cover the allocator mutation and corresponding accounting: merely locking counters after a native allocation/free can reorder events and corrupt a claimed peak. Concurrency and lock ordering therefore require proof. Exported mallinfo itself takes the heap lock, so it cannot blindly be called while that lock is already held.

No telemetry patch, live-hook injection, extra diagnostic firmware or actual heap-peak measurement has been implemented in this iteration. Sparse network polling would at best provide sampled lower bounds and cannot satisfy exact high-water qualification. Do not alter fragment geometry to hide this unresolved working-set issue.

Experiment ordering is explicitly revised: after measured XMB128MiB allocation/free, reviewed P5 failure handling, successful Crucial Recovery update/restart and exact installed-module readback, collect one disposable lightly populated Recovery Restore File System observation (HW002C) before finishing peak instrumentation. This is an exploratory route test, not repair qualification. The previous handoff proposed instrumentation before any repair; that conservative ordering is replaced only for this bounded disposable fixture. Actual peak/context instrumentation remains required before populated/near-full repair or any stable-support claim. Review: research/hw002c-experiment-review.md.
