## Disklabel evidence

FMT-D01. The [older PS3 header](C:/Projects/PS3Firmware/tools/PS3-HDD-Reader/src/fs/ufs/ps3.h:4), upstream [kpartx parser](https://github.com/opensvc/multipath-tools/blob/4cacf3347a51a7975d36109e29c15614bf7fb2ee/kpartx/ps3.c#L6-L32) and archived [Glevand partition patch](https://github.com/sguerrini97/ps3linux-patches/blob/90c8c9c5ec16ac18afd3136b39b80e50475a25df/0035-ps3-partition.patch#L63-L89) corroborate this structure:

| Offset | Length | Meaning supported by these sources |
| --- | --- | --- |
| 0x000 | 0x10 | Reserved/unknown; preserve |
| 0x010 | 8 | BE64 magic 0x000000000FACE0FF |
| 0x018 | 8 | BE64 magic 0x00000000DEADFACE |
| 0x020 | 8 | d_res2; semantics unresolved |
| 0x028 | 8 | d_res3; semantics unresolved |
| 0x030 + i*0x90 | 8 | Entry i p_start, BE64; eight entries |
| Entry +0x08 | 8 | p_size, BE64 |
| Entry +0x10 + j*0x10 | 8 | ACL laid; eight ACL pairs |
| Entry +0x18 + j*0x10 | 8 | ACL rights |
| 0x4B0 | 0x150 | Padding to the source structure's 0x600 bytes |

The intact-table path in [kpartx lines 60-62](https://github.com/opensvc/multipath-tools/blob/4cacf3347a51a7975d36109e29c15614bf7fb2ee/kpartx/ps3.c#L60-L62) requires both full signatures. Starts and sizes use 512-byte sectors in these implementations. Partial signature evidence may identify a damaged candidate; it cannot establish a writable map. These code copies have shared lineage, so corroboration is not three independent hardware qualifications.

FMT-D02. The [public partition research](https://www.psdevwiki.com/ps3/Mounting_HDD_on_PC#PS3_HDD_Partition_Table_(Linux)) describes a 0x1000-byte region, while these structures occupy 0x600. The remaining region, d_res2/d_res3, ACL semantics, replicas/checksums/versioning, customized/OtherOS maps and role identification remain open. Do not infer a partition count from 0x20/0x28 or zero/reconstruct trailing bytes. Repair must preserve the entire observed region until its semantics are known.

FMT-D03. Pinned [UFS2Xplorer gameos.cpp lines 22-47](https://github.com/sagemono/UFS2Xplorer/blob/565ba57e6aabf6996ed4e0512548f4b697183ace/src/ps3hdd_app/gameos.cpp#L22-L47) accepts either low signature half, mixes fixed offsets with table starts, ignores declared lengths and prefers a candidate with more cylinder groups. Whole-disk bounds do not establish partition bounds. This is discovery evidence, not repair authority.

FMT-D04. Our [Ps3DiskLayout.cs](C:/Projects/PS3Firmware/publication/PS3HDDTool/PS3HddTool.Core/Disk/Ps3DiskLayout.cs:25) describes an unsupported PMA layout and later selects a common start without reading its superblock. The bounded source search found no callers of that class in the inspected C# tree. Actual Avalonia [discovery](C:/Projects/PS3Firmware/publication/PS3HDDTool/PS3HddTool.Avalonia/ViewModels/MainViewModel.cs:583) also accepts either signature, and lines 607-645 try entry strides inconsistent with the corroborated table. Exclude both paths as authoritative map parsers. Our migration [RegularImage](C:/Projects/PS3Firmware/publication/PS3HDDTool/PS3HddTool.Core/Migration/RegularImage.cs:31) instead takes an explicit partition sector and crypto profile; its successful migration does not validate automatic discovery.

FMT-D05. Nested starts are relative to their parent VFLASH region in the [older reader](C:/Projects/PS3Firmware/tools/PS3-HDD-Reader/src/device.c:36). Future admission must independently prove child bounds, map identity, overlaps, mixed-zero entries and table occupation. Use half-open intervals; check start and size against parent length before multiplication, and keep map-relative offsets separate from crypto origins. This is a proposed specification requirement, not an implemented parser.

No nested ENCDEC/VFLASH implementation was found in UFS2Xplorer's inspected component tree. Its primitives are technical candidates; its wrappers need exact I/O and checked offset/count/origin arithmetic. Future vectors must cover wrong key/kind/layer, swapped halves, byte order, cropped origins, the first/last nested sector and LBAs above 32 bits. Physical NAND/eFlash encryption is a different region model from HDD-resident NOR VFLASH.

Additional source exclusions: the old reader calls [seek_device(dev,8)](C:/Projects/PS3Firmware/tools/PS3-HDD-Reader/src/device.c:100), while [seek_device](C:/Projects/PS3Firmware/tools/PS3-HDD-Reader/src/util.c:123) takes bytes. Its Fat NOR path initializes a different decryption context from the regular nested read path, and inclusive end tests at device.c lines 256/282 admit one extra sector. Its XTS helper uses host-endian integer stores. These are source findings, not reproduced drive failures; do not adopt this implementation unchanged.

Our legacy UI source logs root/derived key values in [MainViewModel](C:/Projects/PS3Firmware/publication/PS3HDDTool/PS3HddTool.Avalonia/ViewModels/MainViewModel.cs:264) and [MainWindow](C:/Projects/PS3Firmware/publication/PS3HDDTool/PS3HddTool.Avalonia/Views/MainWindow.axaml.cs:698). Exclude that policy from the CLI donor set. Borrow explicit migration key admission and temporary-buffer clearing, then specify no-secret findings/reports and terminal-safe input. This research inspected source behavior only.

## Research closure order

1. Finish named operation/profile requirements. Keep source-derived candidates distinct from supported cells.
2. Complete disklabel reserved-region/ACL/role and competing-map specifications. Reconcile 0x600 parsed structure versus the wider described region.
3. Specify key kind, layer, origin and full-width range arithmetic for full/cropped images; design independent crypto vectors without accessing private keys.
4. Establish PS3 accounting/profile evidence and preserve original conventions. fsbtodb and di_blocks must not be guessed from host presentation.
5. Define trustworthy initialized-prefix/bitmap/table arbitration, final-group reservations and byte-preserving replica policy.
6. Resolve EA payload and feature-flag semantics, then directory/inline/tail details and dirty/pending-free action/refusal rules.
7. Author independent corpus specifications before implementation. Later fixture execution, builds, repairs and native qualification require their own authorization and gates.
