KNOWN CRITICAL ISSUES
- Short/failed reads must never become zero-filled successful metadata.
- Incomplete ownership/traversal must never authorize reclaim or clean markers.
- Current NetBSD EA handling and older disabled EA ownership need adaptation.
- cg_initediblk is an exclusive inode-slot prefix; corrupt-prefix arbitration is
  still open. Our migration core uses /512 di_blocks and does not automatically
  support the published 4096-unit accounting case.
- Saved P13 accounting derives the count factor from fs_fsize/fsbtodb. Native
  shared globals initialize9/512 and have a12/4096 setter selected by an
  internal-HDD IDENTIFY predicate. Complete resets/lifecycle/aliases remain open.
  P13 normalization hardcodes that HDD and maps query failure to false; this
  cannot become an image CLI's profile-selection rule.
  Generic BSD can use stored shift0 with /512 counts; mixed inputs cannot be
  normalized from header values or majority matches.
- The real disklabel has full BE64 signatures and 0x30/0x90 entries; discovery
  heuristics in native and C# donors cannot authorize bounded repair.
- Fat NOR outer CBC and nested XTS need named profiles and explicit origins.
- FreeBSD 8 EA ownership is useful, but its EA content scan is a stub.
- Native P4 VOP/OPDs now bind BE seven-byte EA framing and namespace/access
  predicates. Actual attribute names/value consumers, complete security paths,
  malformed-input and interrupted-update behavior remain open. The native
  parser's unchecked walk cannot be reused unchanged.
- Donor flag bits conflict; preserve/refuse before PS3 semantics are established.
- Legacy byte+0xD3 and new word+0x520 are distinct; do not copy/OR/normalize them.
- Native flag/clean branches and bit0x02->mount0x00200000 dependency-hook link
  are established. ACL/MAC warning paths do not prove value enforcement.
- Kernel bitmap/counters->table preparation->prefix->CG/table scheduling order
  is established; durable order is NOT. P13 repair allocation is a separate
  single-inode path without whole-block initialization/prefix update.
- A donor's probable-end or uncovered USTATE default cannot establish a free
  suffix. Stored prefix, working scan count, actual reads, bitmap/reference and
  ownership evidence remain separate. No disputed lazy-zero/shrink/growth.
- Key kind/layer must be explicit; exclude legacy UI secret logging.
- Orphan/duplicate preservation policy must precede destructive disposition.
- Generic repair journals must cover dirty originals and directory/EA payload.
- No hidden writes from destructors; every durable transition needs recovery.
- FAT/VFLASH, physical hosts and native console profiles qualify independently.
- Complete suite includes acquisition/recovery/backup/migration and FAT/VFLASH;
  a first UFS2 milestone cannot silently drop those tracks.
