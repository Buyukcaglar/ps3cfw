## Dependencies and extraction boundary

Pinned UFS2Xplorer [CMakeLists.txt](https://github.com/sagemono/UFS2Xplorer/blob/565ba57e6aabf6996ed4e0512548f4b697183ace/CMakeLists.txt#L1-L25) declares CMake 3.25, C++20, OpenSSL without an explicit version constraint, and Catch2 3 for enabled tests. Qt is conditional, so a Qt-free native core is a viable source design. [BUILDING.md](https://github.com/sagemono/UFS2Xplorer/blob/565ba57e6aabf6996ed4e0512548f4b697183ace/docs/BUILDING.md#L32-L50) uses classic vcpkg mode; its manifest is therefore not proof of the packages actually resolved by a donor build.

The [declared vcpkg baseline](https://github.com/sagemono/UFS2Xplorer/blob/565ba57e6aabf6996ed4e0512548f4b697183ace/vcpkg.json#L1-L15) is `ce35b1a53aac26d7fcdb8ee1ef7a8e4eea02d27b`. Microsoft's [baseline table](https://github.com/microsoft/vcpkg/blob/ce35b1a53aac26d7fcdb8ee1ef7a8e4eea02d27b/versions/baseline.json) maps OpenSSL to 3.6.1 port revision 2, Catch2 to 3.13.0 and Qtbase to 6.10.0 port revision 1. These are declared baseline values, not chosen CLI dependencies, installed packages or verified donor binary contents. [OpenSSL's licence page](https://openssl-library.org/source/license/index.html) distinguishes Apache-2.0 for 3.0 and later from older terms; select a version before recording the native suite's obligations.

NetBSD's pinned [Makefile.common](https://github.com/NetBSD/src/blob/acb07d978136d3b5a8032fe3dac4b7321db4da1f/sbin/fsck_ffs/Makefile.common#L8-L32) pulls in kernel/shared FFS helpers, snapshot/quota/WAPBL code and libutil/libprop. Source headers use BSD disk/mount/byte-swap interfaces. The reusable unit is an audited algorithm/helper set above our bounded storage and policy interfaces, not the unmodified utility or its entire operating-system environment. [utilities.c](https://github.com/NetBSD/src/blob/acb07d978136d3b5a8032fe3dac4b7321db4da1f/sbin/fsck_ffs/utilities.c#L380-L400) writes directly to its descriptor; those mutations must eventually target an isolated overlay/transaction interface.

The native suite does not automatically inherit .NET/Avalonia runtime dependencies from a C# translation. Our [third-party notices](C:/Projects/PS3Firmware/publication/PS3HDDTool/THIRD-PARTY-NOTICES.md:6) remain source evidence; a future native package needs its own dependency and binary inventory. No dependency was selected, installed or built in this research.
