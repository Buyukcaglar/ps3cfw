What the implementation does
----------------------------
The actual shared C core implements the proposed106-run schedule:
4 calibration runs (10000 empty/event brackets before/after),12 CPU arms,
12 balanced syscall-only/verified-read arms plus2 independent retained-slice
verification reads,9 buffer comparisons,9 logical-placement comparisons,
6 fixed-seed random/locality passes,4 timing-on/off4KiB controls,48 game-file
hash passes. Native request sizes are4KiB,64KiB and1MiB; both data buffers
are4096-byte aligned. Existing-file opens are read-only and allowlisted.

The initial5,595,315,008B proposal remains the main read workload. Explicit
4KiB timing controls add64MiB. A complete normal run returns5,662,423,872B;
90 one-byte EOF requests also consume admission budget even when returning0.
The absolute8GiB cap is charged BEFORE every requested byte, including EOF,
controls, short-read retries and errors; actual returned bytes are tracked
separately. All requests must fit the remaining charged budget. At most64
positive short-read fragments are accepted for one logical request; zero
progress, overreporting, offsets/sizes/hash mismatches and errors stop the run.

Cancellation is serviced at the first of1MiB,64operations or250ms, and before
open. Native syscall stalls have no hard cancellation/time guarantee. The
20minute limit is cooperative.128GiB+2GiB available-space floor is retained.
Close errors preserve the first workload error and separately mark uncertain
cleanup. No automatic deletion, resume, existing-file append or retry is provided.
Read-only opens can still cause filesystem housekeeping; physical zero writes
are not claimed. No ATA, TRIM, cache, power, queue or firmware operations exist.

Ticks use the native timebase/frequency. Per-component histograms use exact
small buckets and <=1.563% relative-width larger buckets, with quantile bounds.
The core stores exclusive scopes; native USB/controller/STOP/render subscopes
are explicitly inclusive and must not be added to their parents. The analyzer
reports syscall-active versus end-to-end rates, paired ratios, CPU and4KiB
instrumentation overhead and unaccounted application time. Hidden filesystem,
driver, crypto and media work remains inside syscall elapsed time.

Each run emits a65536B checksummed record with nonce, stage/range, counters,
timer summaries and complete read/seek histograms.106records occupy6,946,816B.
An8192B receipt,4096B final-publication timing witness and64B DONE token keep
output below8MiB (7,876,672B even at120maximum records). The witness includes
result write/sync/close/reread timings; its own final write/close and DONE are
outside that snapshot. A DONE token can remain after its final sync/close fails;
presence is not proof of process return, final persistence or power-loss safety.
All those failures return error. No collector or stager is supplied.

Review corrections retained in earlier attempt directories
----------------------------------------------------------
The first compile used the wrong context field for a random-range offset.
Old PPU GCC required explicit structure clearing and a freestanding memcpy.
The clock-regression mock initially did not move far enough backward. Windows
stdout text mode expanded binary receipt LF bytes; binary capture now sets
O_BINARY. Record magic lengths and READY/STOP/DONE fixed magic were corrected.
Package EBOOT zero padding is now checked separately from signed wrapper bytes.
Request-budget charging was tightened to count EOF/retries conservatively;
admission-failure journals now finalize the empty SHA; deliberately uninstrumented
and calibration runs do not automatically fail ordinary-loop coverage.
Earlier source/build/test outputs remain preserved, not counted as final passes.
