# HW002M native USB test review

12 October2026. User cannot provide Ethernet and authorizes using the Crucial locally with its own decryption material. Read-only HW002L found that the existing generic migration writer's strict inventory assumptions reject this native volume. No offline filesystem writes are released. The next experiment uses the already installed webMAN to exercise native GameOS writes from FAT32 USB without a bulk network upload.

Local primary source is `tools/webman-source`, commit d1d5b5271dc409677d101220e87024419fa59bcb. `include/file/file_copy.h` recognizes `.66600` only when copying USB to internal HDD, strips the suffix where applicable, keeps the destination descriptor open across subsequent parts, and uses64-bit read positions and sequential cellFsWrite. `include/mount/mount.h` parses exact `&to=` paths and calls file_copy; `include/cmd/mount_copy.h` routes the command. No game/ISO/device-mount path is requested by the experiment.

`include/cmd/cpy_cut_paste.h` reveals a global clipboard mode that can redirect the normal copy command. The experiment clears it before each copy through `/cpy.ps3` on a nonexistent path inside the exclusive own test directory; it never selects a cut/move operation. `include/cmd/md5.h` reports native stat size and MD5. `include/file/md5.h` opens files read-only and streams64/128/256KiB buffers through native cellFsRead. It does not robustly report every read/allocation error; the host therefore requires one unambiguous exact size/hash response and the independent expected digest, not HTTP success alone. A separate tail read at8GiB must match exact expected bytes. Installed binary/source equivalence is not proven just by the observed webMAN version; the canary gates the large operation on actual behavior.

The new Stage-HW002M-Corpus.py has no SSD/network/firmware paths. It guards removable FAT32 F: volume serial and a PowerShell wrapper verifies SanDisk serial/size/nonboot status/free space. Exclusive directory/file creation prevents overwriting. Expected hashes come from an independent sequential generator before staging; generation and complete USB readback both match. SixteenMiB USB canary precedes8GiB data;4MiB/s and30minute limits prevent a repeat of HW002J's avoidable slow transfer. No existing firmware backup is made.

Run-HW002M-NativeUSB.py checks bindings and human readiness before network use. It reads fixed whole installed utility/control hashes; FTP allows only fixed stat/list/new-directory/tail commands. USB split-part lengths and absent next part prevent accidentally joining unrelated data. An exclusive internal directory and absence checks prevent reuse. Exact HTTP command allowlists contain only native hash, clipboard-clear and two copies. Durable intent precedes each mutating GET. No automatic retry, resume, delete, rename, format, repair, kernel-memory/syscall patch or firmware command is implemented. FTP sessions are closed before lengthy copy/hash requests to avoid idle-session ambiguity.

Host tests exercise byte boundaries through8GiB, parser rejection, command restrictions, exclusive destination/mkdir behavior, passive-peer guards and fragmented high-offset readback. They do not establish console behavior. The native copy routine itself has limited error handling; stat/full native hash/exact tail and unchanged controls are necessary acceptance checks, and an unknown outcome must be observed instead of replayed.

This is ordinary file I/O qualification only. Read-only extent mapping, full-capacity/native addressing, crash consistency and repair remain separate. DEV006 still lacks complete allocator coverage/independent full-heap measurement before populated-repair qualification. Preserve the Crucial's unexplained allocations and all historical results. No new firmware or F: firmware operation is needed.
