# P5 full-checker caller review

Primary-agent code/protocol review and separate parser/crypto readback, 11 October 2026. No separate human or agent review is claimed.

The existing sysconf full fsck_cfs,-y,hdd0 caller requests a 32 MiB backing buffer and heap. The captured Crucial geometry needs a 60981796-byte fragment bitmap alone. HW002A now establishes that one 128 MiB allocation from the actual slot1 container succeeds at XMB, is released, and restores the original 166.1875 MiB available memory. The container total is 213 MiB. Remaining 38.1875 MiB during that allocation is an observed XMB value, not guaranteed checker-context headroom.

P5 replaces the same 184-byte function at VA30058..30110 with 46 instructions. It retains its frame, argc3/argv strings, slot1 getter, allocation flags0x200, utility/callback imports and 349 free. Backing and heap are both 128 MiB. Nonzero allocation status or zero output skips the utility and free, then exits with an error; zero-output success uses generic -1. A successful utility return is saved across exactly one free and restored to the existing thread-exit import. No nonvolatile general register is modified. Existing post-thread-exit cleanup is retained if that import returns. Allocation errors cannot enter the utility's default-buffer fallback. This does not claim the UI reports every failure usefully or all repair paths use this function.

Moving instructions changes six type4/6 relocation targets. Ten old in-function records are replaced by six explicitly reviewed records, removing four obsolete argv relocations. Every outside relocation retains its original order and bytes. The relocation segment and decoded ELF shrink by 96 bytes; PT_LOAD sizes and function descriptor are unchanged. No relocation targets the replaced function's interior. No new import, executable cave or geometry change is introduced.

The bounded instruction/dataflow model passes 42 combinations of independently relocated segments, allocation failures/null outputs, successful utility results and returning/nonreturning thread exit. It injects volatile-register clobbers and checks preserved registers, argv, callback, budget, stack/LR, single free and status. This is static/model evidence, not execution on Sony hardware.

Two complete builds produce identical 215764316-byte PUPs, SHA256 50cd0445ec64b801dbd6775fd8f448f61e91fd481ce50a73d54ddb2918281fd1. Separate-parser audit verifies PUP HMACs, changed PKG HMACs/ECDSA, matching PKG/SPKG plaintext headers, SELF section HMACs and full ELF digest. Native and Python full decodes agree. Only sysconf_plugin within dev_flash_005 differs from P4; whole CoreOS, P4 mount fix, admission gates, version, other flash files and padding are preserved. Header changes are limited to required stream lengths/HMACs, decoded ELF length, copied relocation-segment length and digest2. Original SELF signature bytes are retained; changed content relies on the inherited CFW verifier behavior and does not claim Sony authenticity. SPKG verification under its separate public key remains an inherited limitation.

The audit initially imported a historical source-header helper with an import-time report writer. Its rewritten report is verified byte-identical by the prior pinned hash. The audit now supplies only the pure helper and does not replay that writer. All pinned original firmware, previous candidates, NAND inputs and historical review records pass preservation checks.

Release scope is HW002B installation/clean-boot control only. Full checker peak instrumentation, repair-context memory, all recovery/updater checker copies, full-capacity/high-LBA I/O, populated repair, durability, other SSDs and >2TiB remain pending. A larger heap plus clean XMB does not establish stable or data-loss-free support. Do not initiate repair on this release until its next separately reviewed experiment.
